# Decisão 0002 — Requisitos de licenciamento

- **Estado:** ZSL 0.1 publicada como minuta provisória; revisão jurídica pendente
- **Data:** 2026-10-19

## Objetivos confirmados

1. O código será público desde o início.
2. O uso e as modificações para fins pessoais e não comerciais devem ser permitidos.
3. A redistribuição gratuita de versões modificadas deve ser permitida para fins não comerciais.
4. Pessoas e empresas poderão usar o sistema gratuitamente, inclusive em atividades comerciais, sem cobrança por instalação ou dispositivo.
5. Aplicações independentes criadas com o SDK poderão ser comercializadas livremente, inclusive fora do marketplace oficial.
6. Contribuições de código poderão ser propostas por pull requests e incorporadas somente após aprovação do mantenedor.
7. Doações para financiar o projeto serão opcionais.
8. O projeto poderá oferecer serviços comerciais próprios, incluindo atualização automática via SaaS e divulgação paga de aplicações no marketplace.
9. A comercialização do próprio sistema em versões derivadas deverá depender de autorização, sem impedir o uso comercial gratuito do sistema por empresas.

## Questões pendentes

- Redação juridicamente consistente das restrições comerciais sobre versões derivadas.
- Definição de “comercialização” e tratamento de receitas indiretas.
- Direitos concedidos pelos colaboradores e eventual uso de CLA ou instrumento equivalente.
- Compatibilidade com licenças de dependências e componentes de terceiros.
- Política de marca e uso do nome/logotipo ZupiOS.
- Relação entre o código publicamente visível, os direitos de uso e as permissões legais concedidas.

## Estado atual da licença

Foi adicionada ao repositório a **ZupiOS Source-Available License (ZSL) 0.1**, em caráter provisório e sem revisão jurídica. A minuta procura permitir uso comercial interno gratuito, cópia gratuita de versões não modificadas, redistribuição não comercial de versões modificadas e comercialização de aplicações independentes que não incorporem o Software. A distribuição comercial de versões derivadas exige autorização escrita.

A minuta não deve ser apresentada como licença open source convencional. As definições e restrições precisam de revisão jurídica antes de uma versão estável. Alterações futuras não revogam automaticamente direitos já concedidos a cópias distribuídas sob uma versão anterior.

## Nota importante

Este registro descreve os objetivos do projeto e o estado da minuta; não é aconselhamento jurídico. Consulte o arquivo LICENSE e a página de estado da licença para os termos provisórios vigentes.

O modelo pretendido é *source-available* com restrições comerciais, não uma licença open source convencional.
